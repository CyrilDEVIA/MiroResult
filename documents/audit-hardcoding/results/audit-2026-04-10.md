## ⚠️ Points de vigilance à examiner avant toute migration

- **Seuils dupliqués frontend/backend** : les seuils 40/70 apparaissent dans `score.ts` (frontend) ET dans `scoring.config.ts`, `recommendation.service.ts`, `simulation.service.ts` (API). Toute migration doit traiter les deux couches simultanément.
- **Enums Prisma vs table** : `SimulationStatus` et `RecommendationPriority` sont des valeurs fixes → enum Prisma suffisant. Les dimensions scoring sont évolutives → table dédiée plus appropriée.
- **Poids scoring v2** : changer un poids sans ajuster les autres casse la somme = 1. Contrainte à enforcer en code ou DB.
- **Prompts IA** : déplacer vers une table `AIPrompt` implique un chargement asynchrone au démarrage — gérer le fallback si la table est vide.
- **Extensions fichiers** : `ALLOWED_MIMES`, `ALLOWED_EXTS`, `ZIP_MIMES` sont proches mais pas identiques. Centraliser dans un seul fichier `constants/upload.ts` avant de migrer.
- **Ne jamais supprimer une constante** sans avoir vérifié tous ses usages avec `grep -r` sur le dépôt complet.
